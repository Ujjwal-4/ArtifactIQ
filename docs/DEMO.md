# The synthetic demo — what it is and what it proves

`Dashboard → Load Demo Case` (or `POST /api/demo/load`) builds a complete
case numbered `DEMO-<year>-<seq>-<hhmmss>`. Every fixture is **labeled
SYNTHETIC**; the demo never touches real evidence or your case data.

## What gets built

Evidence (6 items, hashed at intake, registered in the custody ledger):

| Evidence | media_type | Contents (SYNTHETIC) |
|---|---|---|
| `sysmon_like_events_SYNTHETIC.json` | json | 5 normalized-relevant events: PowerShell parent/child creation, network connect to `203.0.113.47`, service install `psh-backup`, scheduled task `UpdateCheck` |
| `Security_export_SYNTHETIC.csv` | csv | 12 rows: 7× 4625 logon failure for `svc-backup`, 4624, 1102 log clear, 7045 service, 4698 task, 4688 process with `-` placeholders the parser strips |
| `setupapi.dev.log` (SYNTHETIC) | usb_history | 2 USB device installs (`VID_07AB&PID_FC89…`) |
| `USBSTOR_export.reg` (SYNTHETIC) | registry_export | 2 registry values (`DeviceDesc`, `WriteProtect`) |
| `History` (SQLite, SYNTHETIC) | browser_sqlite | 5 visits + 1 download of `toolpack.exe` at T0+10min |
| `usbstick_demo_SYNTHETIC.FAT16.raw` | disk_image | genuine ~2 MB FAT16 volume (4,090 clusters ≥ the FAT16 threshold), generated by a pure-stdlib builder; `README.TXT` + `SYNTHETI.TXT` + `DOWNLOAD/TOOLPACK.EXE` staged inside — used as real phase-6 analysis input (read-only, sha-checked before/after) |

Story time anchor `T0 = 2025-08-17T22:12:00Z` (drill narrative only).

## What the pipeline demonstrates when it runs

1. **Parsing (p04)** — 5 runs, statuses `completed` (27 events). A parser that
   cannot handle a file would report `failed`/`unsupported` with reasons — the
   demo could show that honestly if you corrupt an evidence copy.
2. **Custody (p05)** — `custody.verify()` returns `ok=true` over a global
   hash chain; manually patching any row (the seeded test does) yields
   "record tampering detected" at that seq.
3. **Timeline (p07)** — ~17 events; `status=completed_with_warnings` because
   one fixture event uses a no-tz timestamp that stays `unparsed` on purpose.
4. **Graph + ATT&CK (p08)** — 8 mapping rows: T1078 (logon burst),
   T1543.003 ×2 (service installs), T1053.005 ×2 (scheduled tasks),
   T1070.002 (audit-log clear), T1059.001 (PowerShell), T1091 (USB media) —
   all with `rule_version=attack-rules/2025a…` and concrete event ids.
5. **Branches (p09)** — B1–B7 next-step *questions* with visible
   `priority` formulas (`priority_calc`), e.g. B5 log-clear gap at priority 90.
6. **Risk (p10)** — score formula `min(100, S*16 + T*14 + C*10 + A*10)`;
   the drill data lands at `score=100, band=critical` with every input visible.
7. **Explanation (p11)** — grounded sentences citing evidence ids; explicit
   "did not come from a model" line when no LLM is configured. The demo builds
   and records it during load (real narrative assembly).
8. **Reports (p12)** — an HTML report is generated during load; html / pdf /
   findings / manifest / custody all generate and download from the Reports tab.
9. **Phase honesty — disk image (p06)**: the demo registers
   `usbstick_demo_SYNTHETIC.FAT16.raw`, a genuine FAT16 volume (pure-stdlib
   builder) staged as synthetic evidence, and runs the **real**
   pytsk3/Sleuth-Kit analysis: the run enumerates its partitions/filesystem and
   records 4 files + 1 dir (`/README.TXT`, `/SYNTHETI.TXT`,
   `/DOWNLOAD/TOOLPACK.EXE` + volume label). Nothing is pre-recorded — if
   pytsk3 is missing the demo degrades to `blocked` for p06 with the install
   hint.

With the engine installed a fresh demo load lands at the full **12/12** phase
counter (statuses counted honestly from `phase_runs`; warnings count as
completed-with-warnings and are listed in the breakdown note).

## Repeatable

Calling `POST /api/demo/load` again creates a *new* timestamped demo case
(`DEMO-2025-002-…`) — demo data is never merged into existing cases.
